<a name="Introduction"></a>
## Introduction

This directory contains data, parameters and code specific to particular VQA projects. As downloaded from the [OpenVQA code repository](https://github.com/ojalaquellueva/OpenVQA) on GitHub, it contains two demonstration projects that can be run "out of the box" to test VQA behavior and provide examples of VQA input and output. Although VQA will detect the projects folder in either location, we strongly recommend that you move this directory ***outside*** the VQA code repository after installing VQA on your system. 

<a name="VQA demonstration projects"></a>
## VQA demonstration projects

The two VQA demo projects are **vqa-demo1** and **vqa-demo2**. See the READMEs inside the project data directories for details of each project.

<a name="Directory structure"></a>
## Directory structure

The top-level folder of the projects directory is called "projects/". Inside, at the next level down, will be one or more project directories. The name of each project directory is also the project code (parameter PROJ) for that project. Parameter PROJ is used a lot by the VQA code. Note that each project directory ("<PROJ>/") contains a data directory ("data/"), a project-specific parameters directory ("params/"), and a project-specific import ("import/"). 

Inside the data directory is the project data directory. It has the same name as the project directory (i.e., "<PROJ>/"). The project data directory contains a raw data directory ("raw/") and one or more assessment directories. Each assessment contains all data (raw data and VQA analysis results) for a single VQA application at a single project site at a single time. Later applications at the same site or new applications at offset sites are kept in separate assessment directories. All raw VQA input data is in directory "raw/". The assessment data directories will be empty prior to analysis. After import and analysis, the assessment directory will contain the normalized VQA input files (in subdirectory "inputs/"), the VQA and QH.net results files (in directory "results/") and report-ready figures generated by VQA (in subdirectory "figs/"). 

Directory "params/" contains the project-specific parameter file (PSP file), named as follows: "params.<PROJ>.R". For example, the name of the the PSP file for project vqa-demo1 is "params.vqa-demo1.R". The PSP file contains all parameter settings needed to run all assessments for a given project. Most are general parameters, copied from the default parameters file ("params.R") in the OpenVQA code repository, although custom import parameters may be added at the start of the PSP file. As the PSP file is loaded after the default parameters file, parameters settings in the PSP file over-ride setting from the default parameters file.

Directory "import/" contains the project-specific import script (PSI script), named as follows: "import.<PROJ>.R". For example, the name of the the PSI script for project vqa-demo1 is "import.vqa-demo1.R". The PSI script contains custom code that normalizes the raw data to the VQA input schema.

The projects directory ***must*** be structured as follows.

```
projects/
 |__<PROJ1>/
 |   |__data/
 |   |   |__<ASSESS1>/
 |   |   |__<ASSESS2>/
 |   |   |__<ASSESS3>/
 |   |   |__raw/
 |   |__import/
 |   |   |__import.<PROJ1>.R    
 |   |__params/
 |       |__params.<PROJ1>.R    
 |
 |__<PROJ2>/ [structure of PROJ2 as for PROJ1]
 |
 |__<PROJ3>/ [structure of PROJ3 as for PROJ1]

```

<a name="Application structure"></a>
## Application structure
* The optimum top level structure of your VQA application should be as follows:

```
vqa/           [Application base directory]
 |__openvqa/   [VQA code directory: all application code]
 |__projects/  [Projects directory: all data and project-specific scripts]

```

<a name="Set up"></a>
## Set up

### How Does VQA find my project?
* VQA knows where to look for the projects directory, as long as (a) you structure your projects directory correctly (see [Directory structure](#Directory structure)), and (b) you keep it in one of two locations:
   1. The original location inside the VQA code directory
   2. The preferred location, one-level up (outside the code directory) in the application base directory (see [Application structure](#Application structure)).
* Once your data directory has been set up, use the commands as shown below in [Usage](#Usage) and [Examples](#Examples). VQA will know where to find and save your data.

### Don’t keep your projects with you code!
* VQA will find and load your data if you keep the project folder in its original location inside the VQA code repository, but please don’t do that! If you are forking VQA to a new repository, you data may rapidly blow up the size of your repository if your dataset is large or the files change frequently. 
* Store your projects outside this repo, one level up. Use this as the default location for VQA projects. 
* If you want to track changes to your data with a versioning software such as git, create a separate repository just for the project. If you also plan to link the local repository to a remote repository on GitHub and are concerned about confidentiality, set the repository to private.

<a name="Usage"></a>
## Usage

### General syntax
* VQA must be run from the command line, either the Terminal application in Linux & Mac OSX, or the RStudio Terminal tab (**not** the Console) in all operating systems.
* After installing VQA, 

```
Rscript vqa.R --mode MODE --project PROJ --assess ASSESS

```
* Options mode, project and assess are all required
* Option mode determines the VQA program to run, and takes on of three values: "import" (import raw data and normalize to VQA input schema), "vqa.batch" (complete VQA analysis of a single assessment) and "qh.net" (Net Quality Hectares analysis of multiple assessments)
* Options project and assess correspond to parameters PROJ (the project code) and ASSESS (the code of an assessment in project PROJ)

Alternatively, you can use short option codes:

```
Rscript vqa.R -m MODE -p PROJ -a ASSESS

```

### Getting help:

```
Rscript vqa.R --h/--help
```

### Running vqa.R as a bash command:
Depending on your environment setup, you may be able to omit the call to Rscript and run vqa.R as a standard bash command as follows:

```
./vqa.R --mode MODE --project PROJ --assess ASSESS
```

To do so, you will need to make the file executable:

```
chmod ug+x vqa.R
```

<a name="Examples"></a>
## Examples

### Example 1: VQA of a single assessment, using vqa-demo1

##### Import raw data

```
Rscript vqa.R -m import -p vqa-demo1 -a main_001_current
```

##### Run VQA analysis on a single assessment

```
Rscript vqa.R -m vqa.batch -p vqa-demo1 -a main_001_current

```

### Example 2: Offset Net Quality Hectares analysis, using vqa-demo2
* This example assumes that you have already completed the VQA analysis of assessments offset_baseline and offset_current.
* Currently, you can only name the current assessment on the command line. You must set the name of the baseline assessment in the PSP file for the project. I will add the baseline assessment as a command line option in the near future.

```
Rscript vqa.R -m qh.net -p vqa-demo2 -a offset_current
```
